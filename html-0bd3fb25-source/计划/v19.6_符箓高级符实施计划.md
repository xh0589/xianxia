# v19.6 符箓·高级符解锁 P1-3 实施计划

> 对标 v18.8 路线图 §4 P1-3：让"高级符"从锁定状态变成可制作、可使用的真实玩法。
> 验收：5 类高级符（战斗/生存/探索/生活/宗门）每类至少 2 张实装，跨战斗/灵田/宗门生效。

## 设计宪法

- 单一真源 + StateRegistry v1 + 镜像非真源
- 不复制战斗/存档系统
- 不引入"日限 N 次"配额
- 六大报告点 + 7 条禁止
- 不动 `talisman-system.js` 现有 state（combatBonuses/shield/escapeBonus）
- 不动既有 4 个 `implemented:true` 符

## 批次 B：TalismanSystem effect 扩展

**文件**：`js/gameplay/talisman-system.js` 末尾追加（不重写）
**新增 effect handler**：
- `attack_damage` → 写入 combatBonuses.attack 持续 1 次（不消耗 bonusActionsLeft）
- `penetrate_boost` → 写入 combatBonuses.penetrate
- `root` / `silence` / `stun` / `freeze` → 调用 `statusEffectManager.addEffect('enemy', ...)`
- `invisibility` → 写入 `state.invisibility = duration`
- `divine_shield` → 扩展 `state.shield += value`
- `escape_boost >= 0.9` → 强制逃跑（直接结束战斗）
- `revive` / `twist_fate` → 玩家 hp=1 / 全员回血 50%（与既有 05-talismans effect 兼容）

**新增方法**：
- `getInvisibility()` → 隐身剩余回合
- `tickTurn()` → 每回合减 1 持续时长
- `applySectEffect(eff)` → 写 `state.sectEffects[key] = {value, expireDay}`

**事件总线**：`talisman:advanced:apply` / `talisman:advanced:fail`

## 批次 C：制作丹方（v19.6 新增 5 张）

**文件**：`js/crafting.js` 末尾追加 `advancedTalismanRecipes`（**仅在 v19.6 module 已加载时合并**）
**示例**（火球符/爆裂符/护山符等）→ 5 张代表性丹方

> 关键设计：v19.6 不修改 crafting.js 主数组，而是用 `window.recipeById` 注入额外 entry，由既有 `executeCrafting` 走旧路径；这样零侵入

## 批次 D：跨系统集成（钩子）

**文件**：`js/crafting/talisman-effects.js`（新文件）
**内容**：
- 灵田催熟：`window.TalismanSystem.applySectEffect({key:'field_ripen', value:30, expireDay: today+10})`
- 寻灵：`window.TalismanSystem.applySectEffect({key:'spirit_detect', value:1, expireDay: today+5})`
- 护山：`window.TalismanSystem.applySectEffect({key:'sect_guard', value:0.5, expireDay: today+30})`
- 警戒：`window.TalismanSystem.applySectEffect({key:'sect_alert', value:1, expireDay: today+3})`

> **注意**：实际"灵田"和"宗门"系统的"护山/警戒"接口是否真的存在 → **不强行接入**；只通过 `TalismanSystem.applySectEffect` 写入，状态保留，等真实系统接入时再读

**StateRegistry**：`talismanConfig`（最近 20 次使用 + sectEffects 列表 + 玩家流派：偏好"战斗符"/"生活符"）
