# v19.7 阵法·玩家布阵循环 P1-4 实施计划

> 对标 v18.8 路线图 §4 P1-4：让"阵法"从文本/参悟变成有"布阵"这一核心动作的玩法。

## 设计宪法

- 单一真源 + StateRegistry v1 + 镜像非真源
- 不复制战斗/存档系统
- 不引入"日限 N 次"配额
- 六大报告点 + 7 条禁止
- 不动 combat-stats.js 主战斗循环（仅 hook 入口）
- 不动 sect-internal.js 宗门系统（仅提供"宗门阵状态"读取接口）

## 批次 C：布阵 API

```js
window.FormationSystem = {
  deployFormation(formationId, target) → {ok, durability, expireDay, cost}
  withdrawFormation(formationId, target) → {ok}
  tickTurn(target) → {consumed, formations, expired}
  getActiveFormation(target, type) → formation
  getBuff(target, attrKey) → pct
  hasBuff(target, attrKey) → bool
  listFormations() → array
  getMaterials(formationId) → array
  getCost(formationId) → number
  getState() → {combat, field, sect}
}
```

**布阵校验**：阵碑材料足 / 灵石够（按首期 1 天消耗）/ 未冲突（同类只能 1 个）
**维持**：tickTurn 减 1 耐久 / 扣灵石（灵石不足 → 阵自动崩溃）

## 批次 D：StateRegistry + 事件总线

**StateRegistry v1** `formationConfig`（export/import/reset）
- activeCombat: {fmt_xxx, deployedDay, durability}
- activeField: {fieldName, formationId, deployedDay, durability}
- activeSect: {sectId, formationId, deployedDay, durability}
- history: 最近 10 次布阵记录

**事件总线 3 个**：
- `formation:deploy` / `formation:withdraw` / `formation:collapse`（灵石不足/耐久耗尽）
