# v19.3 NPC 婚姻 / 后代 / 衣钵 实施计划

> 基线：`仙侠世界_v19.2`（P0-1~P0-5 全部落地 + 4 个 v19.2 收尾）。
> 本计划落实 `计划/v18.8内容深度扩展路线图_网页对标版.md` §5 P0-6：NPC 婚姻、后代、衣钵。
>
> 设计宪法（强制规则.md）：
>   - **轻量版**：不做完整家族模拟器；只做"道侣→后代→衣钵→跨代"4 件事
>   - 单一真源：每 NPC 的 `lineage = { parents, children, master, inheritor }`
>   - StateRegistry v1 持久化；旧档按"无家谱"初始化
>   - 玩家寿终/轮回时**显式选择**"转世本人 / 以传人继续"（不擅自决定）
>   - **不引入"日限 N 次"**：结契是事件、后代是概率、衣钵是死亡触发
>   - 真实影响：后代 NPC 真实入 npcManager、继承灵根/性格/门派关系、活/死/行动

## 2. 数据契约

### 2.1 真源：每个 NPC `npc.lineage`
```js
npc.lineage = {
    parents: [npcId1, npcId2],       // 生父母
    children: [npcId3, ...],         // 后代
    master: npcId | null,           // 师父（亲传）
    inheritor: npcId | null,        // 指定衣钵继承者
    daoCompanion: npcId | null,     // 道侣
    birthDay: int,                  // 出生日（用于年龄计算）
    isFounder: bool                 // 玩家转世标志
}
```

### 2.2 公开 API（全部挂 `window.NpcLineage`）
| API | 用途 |
|---|---|
| `NpcLineage.marry(npcId1, npcId2)` | 道侣结契（含前置校验）|
| `NpcLineage.haveChild(fatherId, motherId)` | 概率生成后代 NPC 入 npcManager |
| `NpcLineage.inheritOnDeath(deadNpcId)` | 师父死 → 衣钵继承（选最优弟子）|
| `NpcLineage.successionOnDeath(deadNpcId, sectId)` | 掌门死 → 继任 |
| `NpcLineage.getAncestors(npcId, depth)` | 查祖先（族谱）|
| `NpcLineage.getDescendants(npcId, depth)` | 查后代 |
| `NpcLineage.recordPlayerDaoCompanion(npcId)` | 玩家结契 |
| `NpcLineage.choosePlayerAfterlife(marriageChildId?)` | 玩家寿终选择"转世/传人" |

### 2.3 事件总线（新增）
- `npc:lineage:married` → `{aId, bId, day}`
- `npc:lineage:childBorn` → `{fatherId, motherId, childId, childName, day}`
- `npc:lineage:inheritance` → `{masterId, inheritorId, artId, day}`
- `npc:lineage:succession` → `{sectId, fromId, toId, day}`

### 2.4 后代 NPC 数据继承
- `spiritualRoots`：父母各 50% 权重（按权重随机选五行）+ ±20 扰动
- `mutatedRoots`：父母 30% 概率遗传
- `personality16`：父母各 50% ±10
- `location`：父母任一 location
- `affection`：0（新生儿）

### 批次 B：后代生成 + 继承

| 步骤 | 内容 |
|---|---|
| B1 | `haveChild(fatherId, motherId)`：5% 概率/年（按 day 推） |
| B2 | 生成新 NPC：spiritualRoots（父母 50/50 + 扰动）+ mutatedRoots（30% 遗传）+ personality16（父母 50/50 ±10）+ age=18 + name（用命名器） |
| B3 | `npcManager.addNPC(newNpc)`（新 addNPC 接口如无则直接 push） |
| B4 | 双方 lineage.children 加入 childId |
| B5 | EventBus `npc:lineage:childBorn` |

**完成定义**：1000 次 haveChild 调用产生 30~80 后代；继承数据与父母相关。

### 批次 C：衣钵继承 + 掌门继任

| 步骤 | 内容 |
|---|---|
| C1 | `inheritOnDeath(deadNpcId)`：选 1 个最优亲传（按 contribution 排序）|
| C2 | 继承内容：1 项亲传技能 → 死者徒弟 skill 池 +1 |
| C3 | 写 lineage.inheritor |
| C4 | `successionOnDeath(deadNpcId, sectId)`：选 sect 内最优弟子升职为掌门 |
| C5 | 接入 `handleNPCDeath`（在 sect-internal.js 末尾追加钩） |
| C6 | EventBus |

**完成定义**：3 个亲传中死 1 个，2 个未死 → 衣钵归 1 个；掌门死 → 长老升掌门。

### 批次 D：玩家侧结契/转世/传人继续

| 步骤 | 内容 |

## 9. 风险与不做清单

### 风险
- **R1 性能**：50 年 2500 天 × 抽样 NPC 数 = 大量后代。**缓解**：只在 NPC 是"活跃夫妻"时跑 haveChild
- **R2 近亲**：家族树过深会自交。**缓解**：查 4 代以内不结契
- **R3 灵根溢出**：父母灵根高 + 扰动 = 200+。**缓解**：clamp 到 0-100
- **R4 掌门死 + 宗门无合适继承人**：**缓解**：选 player（玩家升职）或降级无人继承

### 不做（v19.3）
- 完整家族模拟器
- 联姻外交（宗门之间联姻）
- 多代继承链（仅 1 代）
- 玩家与子嗣同台竞技
