## 批次 A：资源点数据

**文件**：`js/extensions/resource-points.js`

**3 类资源点**：
- spirit_vein（灵脉）：产 spiritStone / 灵气 / 灵水
- mine（矿脉）：产 mat_* 矿物
- herb_garden（药园）：产 mat_* 药材

**字段**（路线图 §4 P1-7 模板）：
```js
{ id, type, name, region, ownerSect, tier, 
  output: {spiritStone: 30, waterEssence: 2}, 
  defense: 120, discovered: true, 
  exhausted: 0.08, // 0~1, 0=满产
  maxExhausted: 0.8, // 超过则停产
  recoverRate: 0.005 // 每天 -exhausted
}
```

**30 张**（10+10+10）：
- 灵脉 10 张：北冥/东海/西荒/中州/南疆/极北/天空/深渊/幽冥/九天
- 矿脉 10 张：玄铁矿/雷晶矿/秘银矿/朱雀矿/寒铁矿/凤凰矿/紫金矿/陨铁矿/星辰矿/龙鳞矿
- 药园 10 张：千灵芝园/万年人参/雪莲谷/何首乌/天心花/地灵根/九叶灵芝/蟠桃园/凤凰血草/五行药田

**初始归属**：60% 无主（10 灵脉/6 矿/6 药 = 22 无主），40% 有主（6 宗门）— 各分布到 4 固定宗门 + 36 门派中抽 6 个

## 批次 B：产出 + 衰减 + 恢复

**yieldPerDay(depleted)**：
- 满产 (exhausted=0) → 100% output
- exhausted=0.5 → 50% output
- exhausted≥maxExhausted(0.8) → 0% output（停产）

**衰减**：每次 yield → exhausted += 0.05
**恢复**：每天 -exhausted += recoverRate(0.005) — 满产需要 160 天无采

## 批次 C：占领 API

```js
window.ResourcePoints = {
  listByRegion(region) / listByType(type) / listByOwner(sectId) → array
  getResource(id) → point
  claim(id, sectId) → {ok, defense, cost, reason?}    // 无主才能 claim（消耗 100 灵石建祠）
  attack(sectFrom, sectTo, pointId) → {ok, victory, casualties, ownerChanged}
  yield(pointId) → {ok, output, newExhausted}
  tickDay() → {recovered: [{id, newExhausted}]}
  getState() → {points, history}
  registerOwnerHook(fn) → fn  // 让 sect-internal 可订阅 owner 变化
}
```

**claim 校验**：资源点无主 / 消耗 100 灵石
**attack 校验**：sectFrom 与 sectTo 不同 / sectFrom 战力 > defense
**yield 校验**：ownerSect 存在 / exhausted < maxExhausted
