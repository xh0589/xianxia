# v19.8 傀儡·玩家制造系统 P1-5 实施计划

> 对标 v18.8 路线图 §4 P1-5：神机门已有傀儡题材，但玩家还不能真正造一个傀儡。
> 验收：4 部件（核心/躯体/武装/灵纹）可拼装出 8 类傀儡；制造消耗材料 + 灵石 + 机关术技能；可执行战斗随从/宗门守卫/采集助手任务。

## 设计宪法

- 单一真源 + StateRegistry v1 + 镜像非真源
- 不复制战斗/存档系统
- 不引入"日限 N 次"配额
- 六大报告点 + 7 条禁止
- 不动 combat-stats / sect-internal 主循环
- 神机门弟子**仅**在制造/维护时有折扣（路线图 §4 P1-5 末段）

## 范围

| 在做 | 不做 |
|---|---|
| 4 类部件：核心/躯体/武装/灵纹 | UI 面板（仅 StateRegistry+API） |
| 8 个傀儡成品（4 核心×2 武装/灵纹组合） | 替换战斗系统 |
| 制造 API：craft/deploy/recall/repair | NPC 自动制造 |
| 4 类任务角色：combat/guard/harvest/transport | 真正接 combat-stats |
| StateRegistry `puppetConfig`（玩家傀儡 + 任务分配） | 神机门 NPC 维护折扣 |
| 部件耐久衰减 + 修复 | 傀儡升级（v20.x） |
| 单元测试 ≥ 30 条 | 浏览器 e2e |

## 批次 C：制造 API

```js
window.PuppetSystem = {
  craft(puppetId, opts) → {ok, puppetInstanceId, parts, cost, reason?}
  deploy(puppetInstanceId, role) → {ok, role, location, startedDay}
  recall(puppetInstanceId) → {ok, yield: {spiritStones, materials}}
  repair(puppetInstanceId) → {ok, cost}
  tickDay(day) → {consumed, decayed, ...}
  listPuppets() → array
  getPuppet(id) → puppet
  getState() → {puppets, deployed, materials}
  getRequiredMaterials(puppetId) → [{itemId, count}]
}
```

**craft 校验**：核心/躯体/武装/灵纹各 1 件齐 / 机关术 ≥ / 灵石够
**deploy 校验**：傀儡无任务中 / 角色 4 选 1
**recall**：返回当日采集/守卫收益（按 tickDay 累计）
**tickDay**：所有部署傀儡 -1 耐久（combat/guard 减 2，harvest/transport 减 1），扣灵石（不足自动召回）

## 批次 D：StateRegistry + 事件总线

**StateRegistry v1** `puppetConfig`
- puppets: [{id, type, parts, durability, deployed, role, deployedDay, totalYield}]
- materials: 玩家当前傀儡部件库存（运行时缓存）

**事件总线 4 个**：
- `puppet:craft` / `puppet:deploy` / `puppet:recall` / `puppet:decay`

## 风险

- R1 性能：tickDay O(n) 遍历玩家傀儡，正常 < 5 个
- R2 真实战斗 buff 接入：v19.8 仅提供 `getState()`，**不接** combat-stats
- R3 真实宗门守卫：deploy location 仅写 state，**不接** sect-internal
- R4 神机门折扣：v19.8 仅预留 `_shenjimenDiscount` getter，**不真正改** 制造消耗
