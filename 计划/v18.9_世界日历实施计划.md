# v18.9 世界日历（WorldCalendar）实施计划

> 基线：`仙侠世界_v18.8`（修罗宫门禁 + 长期闭关 + 宗门资源日结 已在版本记录.md L1–34 落地）。
>
> 本计划落实 `计划/v18.8内容深度扩展路线图_网页对标版.md` §3 P0-1（世界日历 + 长期闭关）剩余的"日历"骨架与体验闭环——长期闭关本身已落地，但**所有确定性事件还没有一张统一的世界日程表**，玩家依旧无法在出关后看到"我不在时世界发生了什么"。
>
> 约束：只做"注册—提醒—摘要"三件事，**不改**已有世界事件/拍卖/秘境/NPC 行为；遵守 `强制规则.md` 的六大报告点与 7 条禁止。

## 1. 设计目标（完成定义，对齐路线图 §15 6/5 标准）

| # | 标准 | 本计划如何满足 |
|---|---|---|
| 1 | 状态真源 | `WINDOW.WorldCalendar` 是唯一真源；StateRegistry `worldCalendar` v1 持久化 |
| 2 | 能保存/读档 | 走 `saveData.modules.worldCalendar`；旧档无该 key 时按空表初始化，**无需迁移** |
| 3 | 有输入 | 注册 API 仅接受显式 `eventId/title/category/dueAbsoluteDay/source`；不允许展示名反推 |
| 4 | 有输出 | 每天 `newDay` 时由 `advance` 推进 + `emit('worldCalendar:due', event)` 给具体系统消费（**消费侧由各系统自愿订阅**） |
| 5 | 有失败/取舍 | 注册事件必须显式 `category`；冲突日程同一天只发摘要不重复弹窗；闭关若越过寿元/硬死线则提前终止 |
| 6 | 有世界后果 | 摘要写入 `WorldCalendarLog[]`（按 category 分桶），玩家可在新面板查看；秘境窗口到期**不**自动消失世界副本（保留原 `DUNGEON_DEFS`） |

## 2. 数据契约（公开 API）

### 2.1 真源：`window.WorldCalendar`

```js
WorldCalendar = {
  // 静态元数据
  version: 1,
  // 状态
  events: [
    // 每条：
    // {
    //   id: 'auction.monthly.<region>.<year>-<month>',   // 注册者保证唯一
    //   title: '帝都坊市月拍',
    //   category: 'auction' | 'sect_event' | 'world_event' | 'dungeon_window'
    //           | 'npc_appointment' | 'tribulation' | 'sect_tournament'
    //           | 'sect_meeting' | 'centennial_gathering' | 'other',
    //   dueAbsoluteDay: <int>,                         // 来自 getAbsoluteDay() 之后的目标日
    //   source: { system: 'auction-service', refId: 'imperial_monthly' },
    //   region: '帝都' | null,                         // 显示用，不参与机制
    //   severity: 'info' | 'remind' | 'major',         // UI 颜色
    //   oneShot: true,                                 // true=触发后自动从 events 移除
    //   payload: { ... }                               // 透传给消费方
    // }
  ],
  log: [
    // { atDay, category, title, summary }
  ],
  // 运行期缓存
  lastAdvancedDay: <int>
}
```

### 2.2 公开 API（全部挂在 `window.WorldCalendar`，禁止重复声明）

| API | 形态 | 用途 |
|---|---|---|
| `register(eventDef)` | `{id, title, category, dueAbsoluteDay, source, region?, severity?, oneShot?, payload?}` → `{ok:true, id}` / `{ok:false, reason}` | 任何系统注册确定性事件（拍卖、宗门大比、秘境窗口、NPC 约定） |
| `unregister(id, reason?)` | `string, string?` → `boolean` | 取消（如玩家错失、剧情被改写） |
| `list({fromDay, toDay, category?})` | 过滤返回 `events[]` | UI 渲染、未来 30/60 日概览 |
| `getNextByCategory(category, fromDay?)` | 返回单条 | UI 角标"距下次 X 还有 N 日" |
| `consumeDue(currentAbsoluteDay)` | `int` → `[{event, logEntry}]` | 由 `onNewDay` 调用：返回当天应触发的事件，**同时把它们写入 log 并移除**（`oneShot:true`） |
| `subscribe(handler)` / `unsubscribe(handler)` | 回调签名 `(event, ctx)=>void` | 让特定系统（如秘境窗口）监听 `worldCalendar:due` |
| `renderPanelHtml()` | → `string` | 给"日程"面板用 |
| `summarizeRange(fromDay, toDay)` | → `{byCategory:{[cat]:N}, items:[log entries]}` | **给"出关摘要"消费** |
| `serialize()` / `deserialize(snapshot)` / `reset()` | StateRegistry 接口 | 存档迁移用 |

### 2.3 事件总线事件（新增 2 个，**不**覆盖任何已有事件）

- `worldCalendar:due` → payload `{event, ctx:{currentDay, source}}`
- `worldCalendar:registered` → payload `{event}`（UI 角标用）

### 2.4 与现有系统的契约

| 已有系统 | 接入方式（**仅注册**） | 消费方式 |
|---|---|---|
| 拍卖 `AuctionService` | 在 `generateNpcLots/generateRoyalLots` 末尾各调用一次 `WorldCalendar.register(...)` | 玩家打开"日程"时只显示**有拍品**的日；触发日由 `consumeDue` 推 `worldCalendar:due`，拍卖服务可自愿订阅做"开市"广播 |
| 宗门事件 `sect-events.js` | 事件 `handleSectEvent` 进入 `activeEvents` 时 `register`；到期 `expiryGameMinute` 转日时 `consumeDue` 自然触发 | 现有触发流程**保持不变**，日历仅镜像展示 |
| 世界事件 `world-events.js` | `WORLD_EVENTS` 命中当日 `register` | 同上，镜像 |
| 长期闭关 `long-retreat.js` | **新增** `startLongRetreatUntilEvent(category, maxDays?)`：把"闭关至下次拍卖"统一接进 `GameScheduler`，通过 `consumeDue` 提前 0 日出关（实际是 `subscribe` 监听对应 category 的 `worldCalendar:due`，在 handler 内 `break` 闭关循环） | 出关摘要消费 `summarizeRange(retreatStartDay, retreatEndDay)` |
| 任务系统 | 不动 | 任务追踪栏可调用 `list` 渲染"任务截止"提醒（**本计划不在 v18.9 内做 UI 联动**，留作 v19.x） |
| 宗门大比/小比/会武 | **暂不实现**（路线图 P0-4 是独立里程碑）；只**预留** `category:'sect_tournament'`，让 UI 早早上线、不返工 |

> **关键约束（路线图 §0 + 强制规则 §"禁止"）**：注册/消费是单向"通知"，**任何系统不得在订阅日历时把日历当作真源**，日历是镜像，行为真源仍在各自系统。

## 6. 六大报告点（强制规则 §"修改前报告"）

1. **涉及状态及其唯一所有者**：`WorldCalendar.events/log`（`js/core/world-calendar.js`）；`GameScheduler` 任务（既有）；长期闭关 `_isInLongRetreat/untilEvent` 标志（既有，仅加标志位）。
2. **公开 API**：见 §2.2 共 11 个，全部挂 `window.WorldCalendar`；事件总线新增 `worldCalendar:due / worldCalendar:registered`；`EventTypes` 常量同步新增。
3. **存档字段**：仅 `saveData.modules.worldCalendar`（StateRegistry v1）；旧档无则按空表初始化，无迁移。
4. **发出/消费事件**：
   - 发出：`worldCalendar:due`、`worldCalendar:registered`、`worldCalendar:summary`
   - 消费方：长期闭关（`cultivation:completed` 不变，新增 `summary`）、拍卖服务自愿订阅（**本计划不在 v18.9 强制接**）
5. **旧存档迁移**：不需要（按空表初始化即可，calendar 100% 由"已发生事件"填充）。
6. **自动 + 人工验收**：见 §5 批次 E1–E4 + 路线图 §0 P0-1 验收 5 条（路径 §7）。

## 7. 与 v18.8 路线图 P0-1 验收标准的对应

| 路线图验收 | 本计划如何满足 |
|---|---|
| 1. 闭关 30 日后，游戏绝对日推进 30 日 | 长期闭关本身已满足；本计划新增"闭关至事件"分支（批次 D1） |
| 2. NPC 年龄/日程/世界事件不被冻结 | calendar 只镜像，不拦截 `newDay`，原有路径不动 |
| 3. 闭关期间不会弹 30 次小事件打断玩家 | calendar `consumeDue` 全部事件→log 一次性聚合；`showMessage` 单条长消息（批次 D2） |
| 4. 出关摘要至少能汇总 NPC、宗门、市场、世界事件四类变化 | `summarizeRange` 按 `category` 聚合；本批次覆盖"市场=auction / 宗门=sect_event+sect_tournament / 世界=world_event / NPC=npc_appointment"四类 |
| 5. 可选择"闭关至下次拍卖/大比"，且不会越过寿元死亡等硬事件 | 批次 D1 `startLongRetreatUntilEvent` + 批次 D4 寿元硬保护 |

> 注意：路线图验收 4 提到"NPC"摘要，本计划 v18.9 内**预留** `npc_appointment` category 的注册入口（百花谷/修罗宫线下 NPC 约会/掌门召见等可由 `npc-life-system` 写入），但**不**在 v18.9 强制接入，留 v19.x；摘要骨架支持这 4 类即可通过验收。

## 9. 风险与不做清单

### 风险
- **R1 镜像失真**：calendar 只是镜像，真源在各系统；如各系统 `unregister` 不及时，列表里会出现"过期未删"项。**缓解**：UI 上把"已过期"用灰色标，且 `consumeDue` 不会二次触发（用 `dueAbsoluteDay < currentDay` 自动归档到 log）。
- **R2 同日多事件轰炸**：`consumeDue` 可能同一天返回 5+ 条。**缓解**：批次 D2 统一走 `summarizeRange` 单条长消息，不逐条弹。
- **R3 `getAbsoluteDay` 跨存档漂移**：time-system.js 的 `getAbsoluteDay` 是 `(year-1)*360+(month-1)*30+day` 派生，无独立真源 → calendar 同样派生，**和 time-system 严格对齐**，不另存。
- **R4 旧浏览器/Node 测试环境无 EventBus**：node 测试用 `node --check` + 手动 mock `window.EventBus.emit`。**缓解**：calendar 在 `init` 内 `try/catch` 包裹注册，未挂 EventBus 时退化为 `console.warn` 而非抛错。

### 明确不做（v18.9）
- 不做"门内小比/宗门大比"系统本体（P0-4 独立里程碑）
- 不做"NPC 自主人生"循环（P0-5 独立里程碑）
- 不做 calendar ↔ 任务追踪栏的视觉融合（v19.x）
- 不做"日历通知中心"独立浮窗（用主面板+角标足够）
- 不改任何"按 X 次数"的旧限制（强制规则 §"禁止无叙事依据的计数器"）
