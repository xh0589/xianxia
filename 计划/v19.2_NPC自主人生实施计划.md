# v19.2 NPC 自主人生 实施计划

> 基线：`仙侠世界_v19.1`（P0-1~P0-4 全部落地：世界日历 + 宗门职位 + 大比）。
> 本计划落实 `计划/v18.8内容深度扩展路线图_网页对标版.md` §5 P0-5：每天给 5~20 个活跃 NPC 推一次"人生行动"。
>
> 重要发现：v18.8 已落地 `js/npcs/npc-life-system.js`（寿元/死亡/治疗 hooks），**但无 newDay 主动推进**。本计划补"每日一次人生行动"。
>
> 约束：遵守 `强制规则.md` 的六大报告点 + 7 条禁止；**不引入"日限 N 次"型配额**（一次行动 = 一次决策）；性能：5~20 NPC/日 ≤ 50ms（路线图 §5 P0-5 性能要求）。

## 1. 设计目标（完成定义）

| # | 标准 | 本计划如何满足 |
|---|---|---|
| 1 | 状态真源 | `NPC_LIFE_STORE[npcId] = { lastActionDay, actionHistory[] }`（StateRegistry 'npcLifeActions' v1） |
| 2 | 能保存/读档 | StateRegistry 持久化 |
| 3 | 有输入 | 每日 tickDay → 抽样 5~20 NPC → 每人选 1 行动 |
| 4 | 有输出 | 行动写入 history；通过 EventBus 广播"江湖传闻" |
| 5 | 有失败/取舍 | 行动可能失败（随机）；玩家闭关期间行动照走 |
| 6 | 有世界后果 | 行动影响：affection ±1 / location 移动 / 物品交换 / 境界微调 |

## 2. 数据契约

### 2.1 真源：`window.NPC_LIFE_STORE`
```js
NPC_LIFE_STORE[npcId] = {
    lastActionDay: int,           // 上次行动日
    actionHistory: [              // 最近 N 条行动（按时间）
        { day, type, summary, result }
    ]
}
```

### 2.2 行动类型（4 类）
- `move`：NPC 换 location（按目标"想游历/想回家"）
- `social`：NPC 与另一 NPC 互动，affection 变化
- `cultivate`：NPC 境界微调（速度按 realm 慢）
- `other`：占位

### 2.3 公开 API
- `NPCLife.tickDay(day)` — 由 newDay 钩入
- `NPCLife.getRecent(npcId, n)` — 查 NPC 最近行动
- `NPCLife.getRumorLog(limit)` — 查江湖传闻

### 2.4 事件总线（新增）
- `npc:action:done` → payload `{npcId, npcName, type, summary, day}`
- 玩家可见"江湖传闻"面板监听此事件

## 5. 批次实施

### 批次 A：骨架 + 抽样算法

**目标**：建文件 + StateRegistry + tickDay + 抽样（5~20 NPC/日）

| 步骤 | 内容 | 自检 |
|---|---|---|
| A1 | 新建 `js/npcs/npc-life-actor.js` IIFE | node --check |
| A2 | `NPC_LIFE_STORE = {}` + StateRegistry 'npcLifeActions' v1 | 导入/导出 |
| A3 | `tickDay(day)` 抽样：取 npcManager.getAllNPCs()，按"最近没行动"优先 5~20 个 | day=1 抽样 5 个 |
| A4 | 单 NPC 行动决策：`chooseAction(npc)` 按目标返回 action | 4 类返回 |

**完成定义**：node 单元测试 ≥ 15 条。

### 批次 B：行动执行 + 影响应用

| 步骤 | 内容 |
|---|---|
| B1 | `move` 行动：10% 概率换 location（随机城市） |
| B2 | `social` 行动：随机选同 location 另一 NPC，affection ±1（带 cap） |
| B3 | `cultivate` 行动：低概率（5%）境界 layer +0.01 进度（连续修炼 36 日升级） |
| B4 | 写入 history + EventBus.emit('npc:action:done') |
| B5 | 同 NPC 同 day 不重复 |

**完成定义**：4 类各 1 断言；history 累加。

### 批次 C：性能 + 集成

| 步骤 | 内容 |
|---|---|
| C1 | 抽样上限 20 NPC/日（路线图 §5 P0-5） |
| C2 | 接 newDay 钩（`processAllSectDailyEconomy` 末尾追加） |
| C3 | 性能：所有决策 O(1) 或 O(n)，总 < 50ms |
| C4 | `applyNpcAction(npc, action)` 改 affection/location/inventory/realm（真实影响） |

**完成定义**：day=10 后 history 累加 ~50-200 条；性能断言。

### 批次 D：玩家可见反馈

| 步骤 | 内容 |
|---|---|
| D1 | 江湖传闻面板：监听 `npc:action:done`，滚动显示 |
| D2 | 宗主可通过 `WorldCalendar` 看 NPC 行动 |
| D3 | `npc.location` 变化后，玩家"找 NPC"时显示新位置 |
| D4 | UI 触发：宗门详情页"江湖传闻"标签 |

**完成定义**：玩家可查最近 30 日传闻。

### 批次 E（可选，留 v19.3）
- NPC 行动与玩家任务关联（玩家可雇 NPC 干活）
- 玩家可阻止/鼓励 NPC 行动
- NPC 跨城结伴移动

**本计划明确不实现 E**。

## 9. 风险与不做清单

### 风险
- **R1 性能**：5~20 NPC × 4 类行动 = 80 次/日决策；每决策 O(1) 即可
- **R2 同 NPC 多日刷同一行动**：用 `lastActionDay === day` 防；NPC 自身 lastAction 防多日
- **R3 行动与玩家任务冲突**：NPC 行走不修改"已存在"玩家任务目标 NPC 位置

### 不做（v19.2）
- NPC 跨城结伴（v19.3）
- 玩家雇/阻止 NPC 行动（v19.3）
- NPC 自创剧情线（v19.3）
