## 一、新建 18 个系统文件

每个文件均为 IIFE 立即执行，函数定义 + window 导出 + onNewDaySubscribe 注册（if typeof）。

### 1.1 天劫战 `js/cultivation/heavenly-tribulation.js`
- **功能**：渡劫期满( tier>=9 )触发多波雷劫战斗 + 中段心魔劫 + 道侣护法减免 + 失败走残魂 + 成功飞升
- **关键函数**：`triggerHeavenlyTribulation` / `startTribWave` / `continueTribWave` / `settleTribulation` / `tribulationSuccess` / `tribulationFailure` / `makeLightningEnemy` / `makeHeartDemonEnemy` / `hasDaoCompanionGuard`
- **波数公式**：`Math.min(9, 3 + Math.floor(tier/2))`（渡劫期 tier=9 → 7 波）
- **心魔劫**：`heartDemonWave = Math.floor(waves/2)`，一票否决（败即走火）
- **护法**：有道侣 bond → 雷劫 attack ×0.7
- **失败**：由 app.js 既有战败流程 `maybeEnterSoulState` + `handleDefeatRevival` 接管，不重复调用
- **成功**：调 `window.onAscension()`（1.3 香火初始化），掉 `mat_sky_iron`×2 + `mat_chaos_stone`×1
- **复用模式**：兽潮清剿多波战斗 UI（`_isBeastTideRaid` + `continueBeastTideRaid`），天劫用 `_isHeavenlyTribulation` 同构

### 1.3 飞升后世界 `js/endgame/ascension-epilogue.js`
- **功能**：香火系统（名气折算信徒）+ 每日香火回馈真元 + 二段飞升（金仙）+ 天界切磋
- **关键函数**：`onAscension` / `dailyIncenseFeedback` / `trySecondAscension` / `tianjieSpar`
- **信徒**：`incense = max(10, floor(fame/2)+10)`
- **每日产出**：`gain = floor(incense*0.5 + random*incense*0.3)`
- **二段飞升**：飞升期 layer>=9 → realm='金仙'

### 1.7 转世轮回 `js/core/reincarnation-system.js`

## 五、设计原则遵守（用户要求）

- **代码结构合理**：复用既有兽潮多波模式/PlayerSect/StateRegistry/onNewDaySubscribe，不复制平行状态；每个新系统独立文件+IIFE+window 导出
- **现实逻辑**：交流不限制次数而模仿厌烦（赠礼 fatigue/爱情冷却 CD/瓶颈首次弹）；善恶有报应；修仙延寿；瓶颈自检；气运可消耗
- **机制平衡**：境界门槛 + 灵石成本 + CD + 概率上限；无全局数值缩放；不读 DOM 作真值；不新增独立 localStorage 角色数据
- **强制规则.md**：每项改动前报 6 项（状态所有者/调用API/存档字段/事件/旧存档迁移/验收）+ 完成后报 5 项；node --check + 端口 8000 验证
